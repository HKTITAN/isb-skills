**Planning Fallacy**: Underestimating time/cost for future while overestimating past performance.
- Root cause: Focus on task specifics ignores lessons from similar projects
- Mitigation: Use historical data from similar projects (reference class), add contingency reserves, break into smaller pieces, involve experienced team
- Impact: Projects consistently overrun; 30-50% typical underestimation

**Optimism Bias**: Underestimating risks, overestimating benefits; confidence in own ability.
- Root cause: Psychological; we believe this project is different (but same biases repeat)
- Mitigation: Outside view (reference class forecasting—what happened in similar projects?), independent review, reduce salience of best-case scenarios
- Interaction: Combines with planning fallacy for compounding underestimation

**Hidden Dependencies**: Projects delay when unknown interdependencies emerge (unknown unknowns).
- Root cause: Complex interactions not visible upfront; assumptions about other teams/external events
- Mitigation: Map dependencies carefully (RACI matrix), consider indirect effects, build schedule slack, involve cross-functional input
- Example: IT project depends on data migration from legacy system managed by different team

**Anchoring Bias**: Initial estimate anchors subsequent estimates even when initial is arbitrary.
- Mitigation: Start with zero-based estimates; discourage sharing initial estimates before team input

**Sunk Cost Fallacy**: Continue bad projects because of prior investment.
- Mitigation: Make go/no-go decisions based on forward costs/benefits only, not past spending
